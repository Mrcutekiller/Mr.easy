Why I Built MR.easy

By Biruk (@mrcute_killer) • August 11, 2026 • 6 min read

I still remember the frustration of watching a beginner try to build their very first webpage. They didn't start with their idea — they started with an avalanche of syntax noise. HTML closing tags, nested <div> elements, class names, CSS specificity rules, npm installations, and build tool configurations before a single title appeared on the screen.

By the time the environment was set up, the initial creative spark was gone. I asked myself a simple question: What if building a website felt like explaining your idea to a friend?

The Problem: Syntax Wall vs. Creative Signal

Modern web development has become heavily over-engineered for simple ideas. Beginners are taught to manage complex toolchains before they understand basic structure. Plain human language should be enough to describe a hero section, a card grid, or a button.

“When syntax gets out of the way, your mind shifts from fighting tags to refining ideas.”

That is why I created MR.easy. Every file starts with Mr.easy "Title". There are no brackets, no closing tags, and no semicolons. Indentation defines structure, and familiar english words describe the UI elements.

The Heritage: The Spirit of Adwa 1896

Building MR.easy in Addis Ababa, Ethiopia gave the project a core identity. Ethiopia has a proud history defined by self-reliance and independence — most famously remembered in the 1896 Battle of Adwa, where resourcefulness and determination prevailed over overwhelming external force.

MR.easy embodies that exact spirit for modern web creators: building our own independent tools from first principles without relying on bloated external dependencies. You don't need a 50MB node_modules folder or a complex framework to build a gorgeous, responsive website.

What Was Hardest to Build

Creating a readable, zero-dependency language in JavaScript was an incredible engineering challenge. The three toughest parts were:

  1. Indentation-based Parsing: Tracking nesting levels without explicit brackets required writing a custom lexer and AST parser that could cleanly process block indentation while remaining fast.
  2. Browser Native Compiler: Bringing the compiler directly into the browser IDE so compilation happens in under 5ms as you type, without calling any external server API.
  3. Instant Visual Feedback: Keeping live iframe previews synced seamlessly with line-number error reporting and CodeMirror editor highlights.

What's Coming Next

MR.easy is growing rapidly into a complete ecosystem for beginner and rapid web prototyping. Over the next few months, we are launching:

  • VS Code Extension: Native syntax highlighting and autocomplete snippet suggestions directly in VS Code.
  • Component Marketplace: Reusable user-submitted UI blocks that can be inserted into any project with one click.
  • Build-time Themes: Output custom CSS color themes (`mreasy build --theme=adwa`) on production builds.
